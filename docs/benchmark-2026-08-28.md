같은 입력을 반복하면 KV 캐시 덕분에 첫 토큰은 빨라졌다. 새 질문에서는 약 1,000~1,300개의 프롬프트 토큰을 CPU로 처리하느라 첫 응답까지 14~20초가 걸렸다. 생성 속도보다 프롬프트 처리 비용이 체감 지연을 더 크게 만들었다.

0.6B 모델은 경로를 인용하더라도 `[출처: 경로: …]`처럼 요구 형식을 자주 어겼고, 7개 질문 중 모든 필수 개념을 담은 답변은 2개뿐이었다. 이 결과로는 진단 정확도를 주장할 수 없다. 다음 실험은 근거 압축, 더 짧은 답변 형식, 1~3B급 모델 비교가 먼저다.

## 검색과 인덱싱 기준선

개발셋 검색은 7개 질문 모두 상위 5개 안에서 정답 문서를 하나 이상 찾았다. 여러 정답 경로를 모두 찾는 Recall@5는 0.9286, MRR은 1.0이었다. 중복 청크를 경로 하나로 합친 Source Precision@5는 0.2833, 청크 단위 Precision@5는 0.3143이었다. 이 질문은 개발 중에 사용한 셋이라 홀드아웃 성능으로 보지 않는다.

2,317개 Markdown 문서와 2,941개 청크의 첫 인덱싱은 8.29초, 변경 없는 재실행은 0.72초였다. 두 번째 실행에서 다시 임베딩한 청크는 0개였다. 기본 해시 임베더는 변경 감지와 회귀 테스트를 위한 장치이지 의미 검색 모델이 아니다.

집계값은 [기준선 JSON](../evaluations/baselines/2026-08-28_x86_64_cpu_qwen3_0.6b_q8.json)에 있다. 질문별 상위 5개 경로·청크·순위·점수는 [검색 원시 증거](../evaluations/evidence/2026-08-28_keyword_dev_top5_raw.json), 답변과 요청별 지연·채점 결과는 [생성 원시 증거](../evaluations/evidence/2026-08-28_qwen3_0.6b_q8_cpu_dev_raw.json)에 추적한다. 생성 증거에서는 로컬 임시 경로와 프로세스 ID만 제거했다. 테스트는 검색 순위에서 지표를 다시 계산하고, 답변을 다시 채점해 집계 JSON의 정확도와 지연 수치를 대조한다.
