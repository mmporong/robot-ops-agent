# 시스템 경계와 안전 원칙

Robot Ops Agent는 로봇을 움직이는 에이전트가 아니다. 문서와 실행 기록을 찾고, 현재 상태를 읽어 진단에 필요한 근거를 모으는 조회 전용 도구다.

```text
PKM·프로젝트 Markdown ──▶ 증분 인덱서 ──▶ SQLite
                                             │
                                             └──▶ search_documents

ROS 2 graph·topic·rosbag·log ──▶ 고정 allowlist ──▶ MCP stdio
                                      │
                                      └──▶ JSONL 감사 로그

검색 근거 ──▶ 로컬 LLM 벤치마크 클라이언트 ──▶ 답변·출처 평가
```

경계는 세 층으로 나뉜다.

1. PKM 계층은 Markdown만 읽는다. SQLite에는 생성 시점의 절대 소스 루트를 기록하므로, 같은 DB를 다른 루트에 연결해 문서를 덮어쓰거나 삭제할 수 없다.
2. ROS 2 진단 계층은 노드·토픽·서비스 목록, 토픽 한 건, rosbag 정보, 허용된 로그만 읽는다. 인자는 고정된 배열로 만들고 `shell=False`로 실행한다.
3. MCP 계층은 검색과 진단 도구를 노출한다. 등록되지 않은 도구와 스키마가 틀린 요청까지 실행 전에 감사 로그에 남긴다.

## 의도적으로 없는 기능

- 토픽 발행
- 서비스·액션 호출
- 프로세스 시작·종료·재시작
- 임의 셸과 임의 파일 읽기
- 로봇 속도·관절·목표 자세 변경

`/cmd_vel`은 현재 발행 내용을 한 건 읽을 수 있지만 새 명령을 보낼 수 없다. `ros_topic_publish`, `shell`, `restart_process` 같은 이름은 MCP 도구 목록에 존재하지 않으며, 호출을 시도해도 외부 프로세스를 만들기 전에 거부된다.

## 감사와 비밀정보 처리

도구를 실행하기 전에 `started` 레코드를 디스크에 쓰고 `fsync`한다. 이 기록에 실패하면 명령을 실행하지 않는다. 완료·실패·거부 결과는 같은 trace ID의 `completed` 레코드로 이어진다. 감사 파일과 인덱스 DB의 권한은 `0600`이다.

인덱서와 진단 도구는 같은 비밀정보 탐지 규칙을 쓴다. 개인 키, AWS 키, GitHub·Slack·Bearer 토큰, JWT, 인증정보가 든 DB URL, `*_TOKEN`·`*_PASSWORD`·`*_API_KEY`·`*_SECRET` 형식의 값은 인덱싱에서 제외하거나 출력에서 가린다.

## 배포 경계

현재 로컬 LLM 수치는 x86_64 노트북 CPU에서 얻었다. Raspberry Pi와 Jetson에서는 실행하지 않았고, 장치에 접속할 수 있는 환경도 확인되지 않았다. 따라서 지금 단계에서 할 수 있는 주장은 `로컬 검색·생성 기준선을 측정했다`까지다. `엣지 배포 완료`나 `현장 로봇 운영 에이전트`라는 표현은 쓰지 않는다.
