# 2026-08-28 의미 검색 개발 기준선

Qwen3-Embedding 0.6B Q8 모델을 llama.cpp의 Vulkan 백엔드로 실행하고 키워드, 벡터, 하이브리드 검색을 같은 7개 개발 질문으로 비교했다. 이 결과는 모델과 검색 경로가 실제로 연결됐는지 확인한 개발셋 수치다. 홀드아웃 성능은 아니다.

## 환경

| 항목 | 값 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 5050 Laptop GPU, 8,151 MiB |

| 모델 | [Qwen3-Embedding-0.6B-GGUF](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF/tree/d20cf9c16f82914a21dbd9c645f56895fb1d7750), Q8_0, 639,446,688 bytes |

| 임베딩 차원 | 1,024 |
| 문서 / 청크 | 2,321 / 3,075 |
| 청크 크기 / 겹침 | 800 / 120자 |

처음 인덱스를 만드는 데 162.33초가 걸렸다. 변경 없는 재실행은 0.75초였고 다시 임베딩한 청크는 없었다. 실행을 마친 뒤 서버 RSS는 830.94 MiB, GPU 프로세스 메모리는 2,837 MiB였다. 인덱싱 중 한 차례 확인한 온도와 전력은 58°C와 47.25W였다. 온도와 전력은 전체 구간 최대값이 아니라 표본이다.

CPU 전용 런타임에서는 공개 문서 11청크가 65.05초 걸렸다. 같은 입력을 Vulkan으로 실행했을 때는 1.72초였다. 이 차이는 작은 스모크 입력에서 잰 값이라 전체 처리량 배수로 일반화하지 않는다.

## 검색 결과

하이브리드는 청크 정밀도가 키워드 기준선보다 높았지만 MRR은 낮았다. 벡터 검색만으로는 키워드 기준선을 넘지 못했다. Qwen 권장 형식에 맞춘 영문 query instruction도 이 7개 질문에서는 수치를 낮췄다. 개발 질문 수가 적고 이미 개발 과정에서 사용한 데이터라 우열을 결론 내리지 않는다.

집계값은 [Vulkan 의미 검색 기준선](../evaluations/baselines/2026-08-28_x86_64_vulkan_qwen3_embedding_0.6b_q8.json)에 있다. 질문별 순위와 점수는 같은 파일의 `evidence` 경로에서 확인할 수 있다.

## 다음 검증

다음 비교는 현재 7개 질문과 분리한 홀드아웃을 사용한다. 로봇별 질문 수를 늘리고, 키워드와 벡터가 서로 다른 문서를 찾은 사례를 따로 모아 실패 유형을 분류한다. Raspberry Pi나 Jetson 수치는 해당 장치에서 같은 모델과 ROS 2를 함께 실행한 뒤에만 추가한다.
