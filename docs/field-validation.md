# 상태 기록 검사기의 현업 효용 검증

## 판단

**현재 판정은 현업 도입 보류입니다.** 명령이 변하는데 관측이 정체되는 증상은 찾지만, 놓치는 조건이 있고 기록 갱신 정지와 실제 기구 걸림을 구분할 근거가 부족합니다. 검출 결과는 사람이 확인할 후보로 사용합니다. 정상 기록 판정, 학습 데이터 자동 승인, 고장 원인 확정으로 사용하지 않습니다.

이 평가는 화면이나 에이전트 명칭의 효과가 아니라 현재 분석기가 무엇을 찾고 놓치는지 확인합니다. 검출기와 단순 기준선을 같은 입력에 실행했습니다. LLM은 사용하지 않았습니다.

## 평가 대상과 정답

| 구분 | 대상 | 측정할 수 있는 것 | 측정할 수 없는 것 |
| --- | --- | --- | --- |
| 실제 기록의 회고적 검사 | 11개 데이터셋 113개 에피소드, 궤적 중복 22개 제외 후 고유 입력 91개·40,716프레임 | 경고 분포, 재실행 일치, CPU 처리 시간 | 독립 정답이 없어 실제 오탐률·미탐률 계산 불가 |
| 완전 합성 통제 시험 | 정상 7개, 주입 오류 10개, 원인 구분 불가 확인용 2개 | 생성·주입 구간을 정답으로 한 조건별 검출과 누락 | 실제 현장의 발생 빈도·종합 정확도 |
| 실제 기록에 값 고정 주입 | 80프레임 이상인 고유 입력 90개 | 주입 전후 경고 변화와 주입 구간 겹침 | 주입 밖이 정상이라는 가정, 실제 오탐률 |

113개 에피소드의 원본 Parquet 해시는 모두 기존 인벤토리와 같았습니다. 이 기록 전체가 과거 0.05/0.1도 후보 기준 선택에 사용됐으므로 신규 홀드아웃이라고 부르지 않습니다. 고유 입력 91개도 독립적인 수집 실험 91회를 뜻하지 않습니다. `_fix` 파생 기록 등 내용이 다른 관련 기록이 포함돼 있습니다.

내용 중복은 원본 파일 이름이나 파일 해시가 아닌, 정렬·단위 변환한 관절 이름·단위·fps·시각·명령·관측값으로 구분합니다. `so101_pick_pm_wrist` 에피소드 0~21은 `so101_pick_pm`의 같은 입력과 중복돼 집계에서 제외했습니다.

알려진 `so101_teleop_bench` 에피소드 0은 기존 사례가 재현되는지 확인하는 용도입니다. 4.4~6.9초·26프레임 구간이 다시 검출됐지만, 새 고장에 대한 검출 성능으로 세지 않았습니다.

## 고정한 검사와 비교 기준

- 현재 검사: 모든 관절의 프레임 간 관측 변화가 0.1도 미만이고, 명령 변화가 하나 이상에서 0.5도 초과인 전환이 3프레임 이상 이어지면 경고합니다. 그리퍼는 기존 구현대로 LeRobot 원단위 차분에 같은 수치를 적용합니다.
- 단순 기준선: 명령과 무관하게 관측 전체가 완전히 같은 전환이 3프레임 이상 이어지면 경고합니다. 산업 도구의 성능을 대신하는 기준선이 아닙니다.
- 두 검사 모두 동일하게 정규화한 입력을 사용합니다. 평가 결과를 본 뒤 임계값을 조정하지 않았습니다.
- 통제 시험 정답은 검출기 출력이 아니라 미리 정한 신호 생성과 값 고정 구간입니다. 프레임 0은 차분이 없어 점수에서 제외합니다. 이벤트는 IoU 0.1 이상인 구간을 일대일 최대 매칭하고 IoU가 높은 이웃부터 탐색합니다. 프레임 TP/FP/FN/TN과 경계 편차도 기록합니다. `minimum_confirmation_delay_frames`는 3개 연속 전환을 확인할 수 있는 최소 지연이며, 오프라인 함수의 실제 알림 지연을 측정한 값이 아닙니다.

## 실제 기록에서 나온 경고

| 검사 | 경고가 있는 고유 입력 | 경고 구간 |
| --- | ---: | ---: |
| 현재 검사 | 13/91 | 83 |
| 단순 반복 기준선 | 91/91 | 2,448 |

현재 검사는 정상적인 정지까지 모두 표시하는 단순 반복 기준선보다 경고가 적습니다. 하지만 독립 정답이 없으므로 이 차이를 오탐 감소나 사람의 작업 시간 절감으로 해석하지 않습니다. 경고가 없는 나머지 입력도 정상으로 확정하지 않습니다.

현재 검사의 경고는 `so101_teleop_bench` 9개 입력에서 76구간, `so101_teleop_v2` 1개 입력에서 4구간, `so101_pick_pm` 3개 입력에서 각 1구간입니다. 마지막 세 입력의 구간은 각각 에피소드 12의 5.9~6.1초, 에피소드 24·26의 0.1~0.3초입니다. 별도의 원인 확인 없이 고장 사례로 세지 않았습니다.

## 통제 시험에서 확인한 범위

| 상황 | 현재 검사 | 단순 기준선 | 해석 |
| --- | --- | --- | --- |
| 정상 정지 | 경고 없음 | 경고 발생 | 현재 검사의 명령 변화 조건이 정지 구간을 걸러냅니다 |
| 정상 추종·느린 추종·일시정지·양자화·그리퍼 움직임·정지 중 작은 센서 잡음 | 정상 7개 시험 전체에서 경고 없음 | 정상 7개 중 3개에서 경고 | 합성 조건에 한정된 결과입니다 |
| 빠른 명령 중 전체 관측 고정, 명령 임계 바로 위, 두 번의 분리된 고정 | 3개 시험·4개 주입 구간 모두 검출 | 모두 검출 | 현재 규칙의 설계 범위입니다 |
| 느린 명령 중 관측 고정 | 놓침 | 검출 | 명령이 프레임당 0.5도에 못 미치면 현재 규칙이 성립하지 않습니다 |
| 100Hz에서 같은 초당 속도로 움직이는 중 관측 고정 | 놓침 | 검출 | 프레임 차분 기준이라 기록 주파수에 영향을 받습니다 |
| 일부 관절만 고정 | 놓침 | 놓침 | 다른 관절의 갱신이 전체 정지 조건을 해제합니다 |
| 팔 상태는 고정, 그리퍼 상태는 갱신 | 놓침 | 놓침 | 그리퍼 갱신이 팔의 문제를 가립니다 |
| 명령이 간헐적으로만 변하는 동안 관측 고정 | 놓침 | 검출 | 명령 변화가 이어지지 않아 경고 구간이 끊깁니다 |
| 2프레임만 고정 | 경고 없음 | 경고 없음 | 두 검사 모두 최소 3프레임 미만은 검사 범위 밖입니다 |

통제 시험은 한 개의 종합 정확도로 합치지 않았습니다. 정상 대조, 현재 설계 범위, 확장 요구, 최소 길이 미만 조건은 의미가 다릅니다. 조건별 프레임 점수와 일대일 이벤트 매칭은 JSON에 보존합니다.

### 원인을 구분하지 못하는 경우

상태 기록이 멈춘 경우와 기구가 막혀 실제 관절이 움직이지 않는 경우는 같은 명령·관측 수열을 가질 수 있습니다. 동일한 입력을 가진 두 통제 사례에서 두 검사 모두 같은 경고를 냅니다. 현재 입력만으로는 어느 원인인지 판정할 수 없습니다. 두 원인은 증상 정답도 같으므로 물리적 걸림에 대한 경고를 오탐으로 세지 않았습니다. 센서 원본 시각·수신 순서·통신 오류·구동 상태 같은 추가 근거가 필요합니다. 이 두 사례는 일반 검출 점수와 분리했습니다.

### 실제 기록에 오류를 넣은 시험

각 기록의 3분의 1 지점부터 최대 30프레임 동안 관측을 이전 값으로 고정하는 시도를 90회 했습니다. 상태값이 실제로 바뀐 시도는 58회이고, 32회는 이미 같은 값이라 입력이 달라지지 않았습니다.

현재 검사의 경고가 겹친 창은 15개였습니다. 그중 7개는 입력이 바뀌지 않았고 원본부터 경고가 있던 창입니다. 유효하게 바꾼 입력에서 새 경고가 생긴 창은 8개였습니다. 이 수치를 정확도나 재현율로 쓰지 않습니다. 주입 지점의 명령이 정지하거나 천천히 변하면 현재 규칙으로는 고정을 드러내기 어렵습니다.

전체 결과에는 실제로 바뀐 프레임 수, 프레임별 관측·명령 변화가 규칙을 만족한 최대 연속 길이, 명령 변화 폭, 원본 대비 경고 변화가 남습니다. 규칙을 만족하게 된 창 15개에 경고가 있었다는 것은 구성 조건의 재현이며 독립 검출 성능을 뜻하지 않습니다.

## 아직 측정하지 않은 것과 도입 기준

- 새로 수집한 기록에서의 성능: 독립 라벨이 있는 신규 기록을 확보하고 검출기 버전을 고정한 뒤 평가해야 합니다. 같은 수집 실험과 파생 파일은 같은 묶음에 둡니다.
- 현업의 오탐·미탐: 검출 결과를 보지 않은 검토자가 원본 시각·영상·기기 로그를 근거로 판정해야 합니다. 근거가 모자란 항목은 판단 보류로 남깁니다.
- 사람의 작업 시간 절감: 같은 문제를 기존 확인 방법과 이 도구로 처리해 시간·누락·잘못된 판단을 비교해야 합니다. 이번 CPU 시간은 사람의 시간 절감을 뜻하지 않습니다.
- 고장 원인 진단: 상태값 반복만으로 원인을 확정하지 않는지 확인해야 합니다.

이 기준이 검증되기 전에는 현업 도입 효과나 자동 진단 정확도를 주장하지 않습니다. 이번 평가는 기능 추가보다 검출 범위와 실패 조건을 드러내는 데 목적이 있습니다.

## 재현

원본 데이터셋과 pyarrow가 있는 기존 LeRobot 환경이 필요합니다. 첫 명령은 CPU에서 Parquet만 읽고, 두 번째는 표준 라이브러리로 검사합니다. ROS 2·시뮬레이터·실물 로봇을 시작하지 않습니다.

```bash
cd "$HOME/robot-ops-agent"
PYTHONDONTWRITEBYTECODE=1 "$HOME/miniforge3/envs/lerobot/bin/python" \
  adapters/bimanual/evaluate_recordings.py \
  --root "$HOME/so101_datasets" --out .local/field-eval/corpus \
  --inventory evaluations/replay/inventory.json
PYTHONPATH=src .venv/bin/python -m robot_ops.replay.field_eval \
  --corpus .local/field-eval/corpus/manifest.json --out .local/field-eval/results
```

`protocol.json`에 검출기·평가기·corpus 해시, 임계값, 생성 시드, 사례별 주입 조건을 실행 전에 저장합니다. `result.json`은 구간별 전체 결과, `summary.json`은 시계열 값을 제외한 요약입니다. 실행 첫 패스는 JSONL 읽기·해시 확인·두 검사·요약을 포함하고, 반복 패스는 메모리에 읽은 같은 입력에 각 검사만 실행합니다. OS 캐시는 통제하지 않았습니다.

공유 가능한 [평가 요약 JSON](../evaluations/evidence/2026-10-16_state_recording_validation.json)에는 원시 관절 시계열·영상·개인 절대경로를 넣지 않았습니다. 원본과 원시 평가 결과는 Git 추적에서 제외된 `.local/field-eval`에 둡니다.
