# 검증 상태와 다음 단계

2026-08-28 현재 독립 프로젝트 저장소로 공개할 수 있는 로컬 개발 기준선까지 왔다. 다만 실제 엣지 장치에 배포한 Robot Ops 제품으로 소개할 단계는 아니다.

## 단계별 상태

| 단계 | 상태 | 확인한 것 | 남은 것 |
| --- | --- | --- | --- |
| 이식 가능한 인덱서 | PASS | CLI 경로 주입, 전체·증분 갱신, 수정·삭제·이름 변경, 해시, 비밀정보 제외, 소스 루트 격리, llama.cpp 배치 임베딩 연결·실측 | 다른 호스트 재현 |
| 로봇 도메인 검색 | PARTIAL | 7개 개발 질문, 데이터셋 해시, 키워드·Qwen3 벡터·하이브리드 비교, 원시 순위 추적 | 조건 분리 홀드아웃, 실패 유형별 질문 확장 |
| 조회 전용 MCP | PASS | 10개 조회 도구, 미등록 도구·스키마 오류·프롬프트 인젝션 차단, 실행 전 감사 기록 | 실제 장시간 ROS 2 운용 중 동시성 검증 |
| 로컬 모델 기준선 | PASS | Qwen3 0.6B Q8, x86_64 CPU TTFT·P50/P95·tokens/s·RSS·답변·인용 평가 | 더 큰 모델 비교, 근거 압축, OS 수준 네트워크 차단 검증 |
| 사용자용 진단 루프 | NOT IMPLEMENTED | 검색·ROS 2 조회·생성 벤치마크를 각각 검증 | 질문부터 근거 검색·추가 조회·출처 답변까지 연결한 `robot-ops ask` |
| 수정안 제안·검증 | NOT IMPLEMENTED | 쓰기·구동 명령을 차단한 안전 경계 | 실제 적용 없는 diff 생성, 테스트·시뮬레이터·rosbag 검증, 사람 승인 경계 |
| 실제 엣지 배포 | NOT MEASURED | 없음 | Raspberry Pi·Jetson 장치 정보와 접속 권한부터 필요 |
| 서비스화·재현 | PARTIAL | CLI, SQLite, MCP stdio, 고정 테스트·평가 명령 | API·UI, 재부팅 서비스, 장시간 모니터링 |

llama.cpp의 `--offline` 플래그와 localhost 바인딩은 사용했다. 다만 현재 호스트에서는 사용자 네트워크 namespace 생성이 허용되지 않아 OS 수준 네트워크 차단 상태를 만들지 못했다. `--offline` 사용을 곧바로 `네트워크 차단 검증 완료`로 해석하지 않는다.

의미 임베딩 클라이언트는 숫자 루프백 주소의 `/v1/embeddings`만 허용한다. 시스템 프록시와 HTTP 리다이렉트도 사용하지 않는다. 이 안전 검증은 검색 성능 평가와 별개다.

Qwen3-Embedding 0.6B Q8을 Vulkan으로 실행한 개발셋 비교에서는 하이브리드의 Chunk Precision@5가 0.4000, 키워드 기준선이 0.3143이었다. 반면 MRR은 키워드 1.0, 하이브리드 0.9286이었다. query instruction을 붙인 결과도 더 낮았다. 서로 다른 지표가 엇갈리고 질문이 7개뿐이라 `검색 정확도를 개선했다`고 쓰지 않는다.

## 현재 쓸 수 있는 주장

- 로봇 문서 2,317개를 경로 주입형 SQLite 인덱스로 옮기고, 변경 없는 재실행에서 2,941개 청크의 재임베딩을 0건으로 만들었다.
- Qwen3-Embedding 0.6B Q8과 Vulkan으로 2,321개 문서를 162.33초에 인덱싱하고, 키워드·벡터·하이브리드의 개발셋 결과를 같은 지표로 비교했다.
- JD-AMR, SO-101, 차동구동 로봇, Isaac 실험 문서를 같은 검색 구조에 넣고 개발 질문 7개의 검색 기준선을 측정했다.
- ROS 2와 rosbag·로그를 읽는 MCP 도구만 노출하고, 이동 명령·임의 셸·프로세스 제어를 allowlist 밖에서 차단했다.
- Qwen3 0.6B Q8을 x86_64 CPU에서 실행해 첫 토큰 지연, 전체 지연, 처리량, 메모리, 답변 개념과 인용 경로를 함께 측정했다.

수치는 개발셋과 현재 노트북 조건을 함께 밝혀야 한다. `정확도를 높였다`, `로봇 운용 시간을 줄였다`, `오프라인 환경을 검증했다`, `엣지에 배포했다`는 아직 쓸 수 없다.

## 독립 프로젝트로 두는 이유

JD-AMR 애플리케이션은 주행과 로봇 상태 생성이 책임이다. 이 저장소는 여러 로봇의 문서·ROS 2 상태·rosbag·로그를 조회하고, 검색과 진단의 근거를 평가하는 공통 계층이다. 실행 경계와 평가 방법이 특정 로봇 코드에서 분리돼 있어 독립 프로젝트로 유지한다.

현재 독립 프로젝트의 범위는 로컬 Robot Ops RAG와 조회 전용 진단 도구다. 다음 조건을 모두 확인한 뒤에만 실제 엣지 운영 프로젝트로 범위를 넓힌다.

1. 두 종류 이상의 로봇에서 같은 진단 흐름을 재현한다.
2. 실제 Raspberry Pi 또는 Jetson에서 모델과 ROS 2를 동시에 실행한다.
3. 재부팅 재현, P50/P95 지연, RAM, 온도·전력 대리 지표, OOM·스로틀링을 기록한다.
4. 성공 답변과 틀린 진단, 위험 명령 차단을 한 화면이나 영상으로 보여 준다.
5. 개발 질문과 분리된 홀드아웃으로 검색·진단·출처 정확도를 다시 평가한다.

현재는 여러 로봇 문서에 같은 검색·진단 구조를 적용하고 로컬 CPU 기준선을 측정했다. 엣지 실측이 없으므로 프로젝트 이름과 소개에서 `엣지 배포 완료`, `현장 Robot Ops Agent`라고 표현하지 않는다.
